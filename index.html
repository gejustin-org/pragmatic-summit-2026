Talk 01

How AI is Reshaping the Craft of Building Software

Vijaye Raji (CTO of Applications, OpenAI) & Tibo Sottiaux (Head of Engineering, Codex) · Fireside chat with Gergely Orosz

TL;DR

OpenAI's internal engineering has shifted from using Codex as a tool to treating it as a teammate. The Codex team reinvents its workflow weekly, chasing shifting bottlenecks — first code generation, then code review, now user understanding and strategy synthesis. Their engineers routinely consume hundreds of billions of tokens per week, running parallel agents from reserved dev boxes while attending meetings.

Key Insights

  1. The bottleneck keeps moving. Code generation → code review → CI/CD → understanding user needs. Every time you solve one, the next stage becomes the constraint.
  2. Codex is responsible for its own QA. They run Codex overnight in a self-testing loop that performs autonomous QA, flags regressions, and generates PDF reports.
  3. Designers ship more code than engineers did 6 months ago. Designer-authored code is merge-ready. Role collapse is happening at the frontier.
  4. "Compute envelope per employee" is the new negotiation. A candidate asked how much compute they'd get — the new version of "what's the equipment budget?"
  5. Explore multiple implementations in parallel, pick the winner. Spike approaches simultaneously, converge on whichever proves best. This kills the design doc bottleneck.
  6. The PM as 10x program manager. The sole PM for all of Codex uses it to auto-file tickets, assign work, and follow up — becoming a "50x program manager."
  7. New grads are AI-native and crushing it. ~100 new grad hires this summer. The "juniors are dead" narrative is wrong.
  8. Foundations never go out of fashion. Architectural thinking, product intuition, and ability to move up and down the stack remain durable skills.

Notable Quotes

"Some of the engineers routinely hit hundreds of billions of tokens every week."

— Vijaye Raji

"Every time I think I'm more capable than Codex, I figure out I'm wrong and I just didn't prompt it right."

— Unnamed OpenAI researcher, per Tibo

"Our designers are shipping more code than engineers were shipping six months ago."

— Tibo Sottiaux

"I don't think I've ever seen anything like this... the speed at which this is happening, some of these charts don't make sense."

— Vijaye Raji

Data Points

~100New grad hires at OpenAI this summer
33Direct reports for Tibo (flat structure)
100B+Tokens consumed per engineer per week

Connections to Our Work

  • Bottleneck migration is directly relevant. As you enable faster code generation, proactively invest in code review automation, CI acceleration, and deployment pipelines.
  • The PM-as-program-manager pattern could inform how context engineering work is structured — one person + agents doing the work of a small team.
  • "Compute envelope per employee" is a framing to bring to leadership. Frame AI spending as a talent perk, not a cost.
  • Parallel implementation exploration could reshape how migration strategies are approached — spike multiple approaches with agents, converge on what works.
Talk 02

Lessons from Building Cursor

Sualeh Asif (Co-founder, Cursor) · Fireside chat with Gergely Orosz

TL;DR

Cursor's co-founder reveals that coding "got solved in six months" (March–December 2025) and the best engineers no longer write code by hand. The real frontier is cloud agents that can test their own code, self-driving codebases where you allocate a compute budget, and RL-trained models that learn to self-summarize for infinite context. Engineers will increasingly become managers of agent fleets.

Key Insights

  1. "Coding got solved in six months." From March to December 2025, hand-coding went from default to obsolete for the best engineers. Engineering didn't get solved, but the specific act of writing code did.
  2. Cloud agents are at 1% of their potential. To reach 90%, usage must grow 1000x. The fundamental change needed: models that test their own code.
  3. DevX is the cloud agent bottleneck. Models need to use your app like a human would, but corporate DevX is held together by tribal knowledge. The model never complains about bad DevX — it silently degrades.
  4. Self-driving codebases are coming. Allocate $100K/day to your codebase. 7% on security, 12% on tech debt, 25% on bug finding, 50% on backlog. The codebase manages itself.
  5. RL-trained self-summarization solves context limits. RL forces the model to produce summaries actually useful to its future self — lossy, but like human memory.
  6. Composer 1.5 is between Sonnet 4.5 and Opus 4.5 — trained almost entirely through RL. Custom models matter.
  7. The browser experiment revealed genuine surprise. The model built a functional browser from scratch over 3 days with ~4000 commits — something Sualeh himself couldn't do.
  8. Review every line for long-lived code. Don't bother for weekend projects.

Notable Quotes

"Coding got solved in six months… that doesn't mean engineering is done and there's no engineers anymore. But the best engineers I know are not writing code by hand anymore."

— Sualeh Asif

"You press enter, come back, and you see a thousand line diff and you have no clue whether it's mergeable. It should be the model's responsibility to figure out if it's correct."

— Sualeh Asif

"I can't do this. If you gave me Composer 1.5 and let me rip for a month on an island, I probably couldn't make a browser."

— Sualeh Asif

Data Points

1%Current compute on cloud agents (target: 90%)
~4,000Commits to build a browser in 3 days
$100M+CPU compute/year for RL infrastructure

Connections to Our Work

  • "The model never yells at you when DevX is off" — think about model-facing DevX alongside human-facing DevX. Are your repos and docs navigable by agents?
  • Self-driving codebase concept maps to migration automation — allocate persistent compute to continuously upgrade/maintain the codebase.
  • RL-trained self-summarization is relevant to context engineering — the best context isn't hand-crafted, it's learned through optimization.
  • Cloud agent testing aligns with AI quality validation. The next step is generating verified code.
Talk 03

Lessons from Building Vercel v0 and the d0 Agent

Malte Ubl (CTO, Vercel) · Fireside chat

TL;DR

Vercel's CTO rebuilt their internal data agent by deleting everything and replacing a complex tool-calling architecture with just two tools: bash and SQL — 50 lines of code. Make problems look like coding tasks because that's what models are trained on. He also argues for "optimistic locking" organizational models, predicts software is "a free puppy" (free to create, expensive to maintain), and caps Vercel at 1,024 employees.

Key Insights

  1. Delete everything and start simpler. d0 went from complex tool-calling to 50 lines with bash + SQL. YAML descriptions of business semantics proved more powerful than tool orchestration.
  2. "In the world of agents, you have to be humble." Best practices from summer 2025 are already outdated.
  3. Optimistic locking for organizations. No approvals. Ship anything but announce intent. The org can veto. This inverts the traditional approval bottleneck.
  4. Software is a free puppy. Free to create, expensive to maintain. The exciting frontier is agents in software maintenance.
  5. The software market elasticity question. Cheaper creation → more software (YouTube analogy), not fewer engineers.
  6. Senior ICs benefit most, then juniors. Seniors already operated like managers of work. The squeeze is in the middle.
  7. One person should prove the product before getting a team. "Teams just make things go slower."
  8. 1,024 employees as an asymptote. Revenue grows, headcount doesn't.

Notable Quotes

"We deleted everything and switched to an agent that looks very similar to a coding agent… just two tools: bash and SQL. 50 lines of code. Completely transformational for the business."

— Malte Ubl

"Software is free. Like getting a free puppy. It has to be maintained."

— Malte Ubl

"If I were to start v0 today… why would you have a team? Teams just make things go slower."

— Malte Ubl

Data Points

50Lines of code for d0 agent
2Tools: bash + SQL
87%Support intake automated
1,024Employee count cap

Connections to Our Work

  • "Make it look like a coding task" — present migration specs as code-like artifacts, not abstract instructions.
  • Deleting complexity — consider whether bash + your domain-specific tool could replace complex agent pipelines.
  • Free puppy maintenance is the migration automation opportunity. More AI-created software = exploding maintenance burden.

Talk 05

Leading Engineering Through an Agentic Shift

Anshu Chada (Head of Developer Platform) & Ty Smith (Principal Engineer) · Uber

TL;DR

Uber built Minions (background agents), U-Review (AI code review), AutoCover (test generation), and AutoMigrate with Shephard (campaign management). 70% of agent workloads are toil — migrations, dead code cleanup, upgrades. The shift from pair programming to peer programming yields the biggest gains. The hardest problems aren't technical; they're adoption, measurement, and cost.

Key Insights

  1. 70% of agent workloads are toil. Migrations, library upgrades, dead code cleanup. Higher accuracy creates a virtuous cycle of trust and adoption.
  2. From pair programming to peer programming. Copilot era: 10-15% bump. Agent era: developers as tech leads directing async agents.
  3. Prompt quality matters enough to build a grader. Minions has a "prompt improver" that analyzes prompts before execution.
  4. Code review is the new bottleneck. Code Inbox (smart routing + risk scoring) and U-Review (AI review with a grading layer) address the flood of AI-generated PRs.
  5. AutoCover generates 5,000 tests/month with 3x quality vs. generic agents — purpose-built with RL-style optimization.
  6. AutoMigrate + Shephard is the migration holy grail. Four phases: identification → transformation → validation → campaign management.
  7. Adoption is slow despite magic demos. Peer-to-peer win-sharing is the most effective tactic.
  8. Activity metrics ≠ business outcomes. The CFO asks "what's the impact on revenue?" This is unsolved.
  9. Cost is 6x since 2024. Right model for the right job, but minimize developer friction in model selection.

Notable Quotes

"70% of the workloads that developers are pushing into the system were toil tasks."

— Anshu Chada

"Engineers trust other engineers as opposed to directors like me."

— Anshu Chada

"The cost of AI is too damn high."

— Anshu Chada

Data Points

70%Agent workloads that are toil
5,000AI-generated tests merged/month
3×Quality improvement vs. generic agents
6×Cost increase since 2024

Connections to Our Work

  • AutoMigrate + Shephard is the architecture blueprint for migration automation. Four phases: identification → transformation → validation → campaign management.
  • Prompt improver pattern — invest in prompt quality checking before execution. Failed tasks kill trust.
  • 5,000 tests/month validates dedicated-agent-per-task over generic agents.
  • "Engineers trust engineers, not directors" — find champions, share wins, let adoption spread peer-to-peer.
Talk 06

Lessons from Building a New AI Product

Nik Koblov (EVP Eng), Veeral Patel, Will Koh, Ian Tracey (Staff Engineers) · Ramp

TL;DR

Ramp went from "a thousand agents" to "a single agent with a thousand skills," centered on Omnichat and a shared tool catalog. Their policy agent demonstrates the power of starting simple with real data. Ramp Inspect now accounts for 50%+ of merged PRs. Team A (impact-obsessed, tool-adopting) will diverge sharply from Team B (process-obsessed, headcount-complaining).

Key Insights

  1. One agent with a thousand skills > a thousand agents. Let experimentation bloom, then ruthlessly consolidate.
  2. English is the new programming language — for real. The policy agent works by turning the expense policy doc into the rules. The doc IS the prompt.
  3. Start simple, learn from live data, layer complexity. Each layer added based on observed failures, not predicted needs.
  4. Users are wrong. They assumed user approvals were ground truth. They weren't — users are lazy, don't know the policy, or just approve on Sundays.
  5. Build your own eval tools with Claude Code. They "one-shotted" a custom Streamlit eval tool. Sometimes building > buying.
  6. Evals from day one, starting with 5 data points. Run in CI. "More likely than not, adding more context will have bad consequences — context rot."
  7. The autonomy slider. Let users control the autonomy level. Trust builds over time; let users pull toward more automation.
  8. Ramp Inspect: 50%+ of merged PRs. Multiplayer-first so PMs and designers can pair with engineers.
  9. Team A vs. Team B divergence. AI amplifies the gap. "You can still build the wrong thing just a lot faster."

Notable Quotes

"You don't need to build a thousand agents. You want to drive your framework towards a single agent with a thousand skills."

— Nik Koblov

"AI products cannot be one-shotted. As long as everyone is aligned that you're not going to have perfection on day one, that was one of the main cultural learnings."

— Veeral Patel

"Software is perpetually not finished. Jobs not finished."

— Ian Tracey

Data Points

50%+Of Ramp PRs from Ramp Inspect
150K+Tests in their suite
~20Tools vibe-coded by one PM

Connections to Our Work

  • "One agent with a thousand skills" — build a shared agent framework with pluggable migration skills.
  • The autonomy slider — let teams control how much they trust AI-generated migrations.
  • "Context rot" — more context ≠ better results. You need evals to know.
  • Team A vs. Team B — a useful framework for evaluating engineers in the AI era.
Talk 07

Leading High-Performing Engineering Teams in the Age of AI

Nicole Forsgren, PhD — Author of Frictionless & Accelerate, Google · Fireside chat with Gergely Orosz

TL;DR

AI supercharged the coding "inner loop," but organizational friction — reviews, deployments, access provisioning — is now the dominant bottleneck. Faster AI feedback loops paradoxically increase cognitive load. Humans max out at 3-4 hours of deep work per day. Build a "personal board of directors" to navigate uncertainty.

Key Insights

  1. The bottleneck has moved downstream. AI made coding fast; review, deployment, release, and security processes are on fire.
  2. Faster feedback loops ≠ better. AI feedback is so fast that engineers rebuild mental models "dozens of times in 30 minutes." Mitchell Hashimoto's workaround: turn off all agent notifications.
  3. Cognitive load is the real limiter, not tools. Humans max out at 3-4 hours of deep work per day. "1000x engineer" narratives are bounded by human cognition.
  4. Burnout isn't overwork — it's values misalignment. The fear isn't job loss, it's losing connection to craft.
  5. AI genies aren't friends. Six agents ≠ six teammates. Agents "just agree with us constantly" — worse than honest peer pushback.
  6. SPACE framework still works. Satisfaction, Performance, Activity, Collaboration, Efficiency. Use adoption as a proxy for satisfaction.
  7. For agents to self-drive, humans must first understand the system. Agentic future requires observability — which requires humans who can build it.

Notable Quotes

"We just threw gas on the fire, and now our systems — whether technology systems or human systems or processes — are really getting overwhelmed."

— Nicole Forsgren

"Humans max out at about 3 to 4 hours a day of really hard deep work. Which always makes me laugh when execs say they need 8 hours of intense work."

— Nicole Forsgren

"Having a couple of genies is different from having a couple of friends."

— Nicole Forsgren

Data Points

3-4 hrsMaximum deep work per day
2 weeksNew hire's first contribution sat unreviewed
10%Sanctioned AI experimentation time (Atlassian)

Connections to Our Work

  • Context engineering should reduce cognitive load, not add to it. Migration automation should eliminate mental model rebuilding.
  • Instrumentation before agentic — invest in migration observability before fully autonomous agents.
  • DORA → SPACE → DevX → Frictionless — Forsgren's evolution tracks the same trajectory as AI Capabilities Model work.
Talk 08

Frameworks for Reinventing Software, Again and Again

Martin Fowler (ThoughtWorks Chief Scientist) & Kent Beck (Creator of XP & TDD) · Fireside chat with Gergely Orosz

TL;DR

Two legends with 50+ years of combined perspective: nobody has the answers right now, and that's both terrifying and liberating. They warn about "re-soloing" of programming, advocate for pair programming with genies, and argue that craft skills are more relevant with AI — but the emotional satisfaction of craft is changing fundamentally.

Key Insights

  1. "Nobody knows the answers to anything." For 25 years, senior engineers could press play on known solutions. That era is over. The new meta-skill is figuring out how to use these tools.
  2. AI's magnitude is unprecedented. Fowler: nothing matches it — not OOP, not the internet, not Agile. Beck: the microprocessor is the closest analogy.
  3. The Agile Industrial Complex will repeat with AI. The pattern of snake oil (SAFe, certifications) is already visible.
  4. The "re-soloing" of programming is dangerous. Engineers say "I have 6 agents" — but that's tools, not human collaborators who disagree with you.
  5. "DevX = Agent Experience" is a circle. Well-modularized code, good tests, clean APIs, clear domain language — all help agents AND humans.
  6. Pair programming: 2 humans + N genies, not 1 human + N genies. The slowness of agents is a feature — while waiting, humans discuss architecture.
  7. Kent Beck's emotional honesty about losing craft satisfaction. "I need to let go of that because it doesn't make a difference anymore." A legendary craftsman mourning the loss of what gave him joy.
  8. Domain language is the new craft. Developing precise language to communicate with agents is the new high-leverage skill — DDD reborn for the AI era.

Notable Quotes

"At this moment, nobody knows the answers to anything."

— Kent Beck

"I can't do that anymore. But I can still develop an overall understanding of what I'm doing. I need to shift my focus to enjoying understanding the domain… it just doesn't have leverage anymore."

— Kent Beck

"AI is an amplifier. If you're young and learning quickly, AI is going to amplify that. This is the golden age of the junior programmer."

— Kent Beck

"My skepticism has to be absolute and total, which means I have to be skeptical about my skepticism."

— Martin Fowler

"If you're a carpenter and they just introduced the circular saw and you think carpentry is over — no, you have more powerful tools."

— Kent Beck

Connections to Our Work

  • "DevX = Agent Experience" — everything built for developer productivity also makes agents more effective. The ultimate argument for AI Platform investment.
  • Re-soloing warning — advocate for pair/mob programming WITH agents, not solo + agent workflows.
  • Domain language for migrations — develop precise terminology (campaign, target, rollback, conformance) that agents can use consistently.
Talk 09

Engineering Practices That Make Coding Agents Work

Simon Willison — Creator of Datasette, co-creator of Django · Fireside chat

TL;DR

The most directly practical talk. Willison has fully transitioned to agent-first development — he writes more code on his phone than his laptop. TDD is mandatory (agents make it free), conformance-driven development enables reverse-engineering specs from multiple implementations, and sandboxing is the primary security control. Most provocative: we're approaching "nobody reads the code" — and it might work.

Key Insights

  1. TDD is now mandatory, not optional. Tests used to be "extra work." Now they're free. use red green TDD — 5 tokens is the complete instruction.
  2. "Nobody writes code, nobody reads code" — and it might work. If you build verification infrastructure (tests, conformance suites, manual testing). We already trust other teams' code without reading it.
  3. Conformance-driven development is a breakthrough. Build a test suite that passes against 6 existing implementations, then use that reverse-engineered suite to build a new implementation.
  4. Code quality is a choice. Poor AI code is YOUR choice — you chose to accept it. With agents, you can achieve higher quality because refactoring costs just a prompt.
  5. Agents follow existing patterns almost perfectly. The first implementation matters enormously — "exactly the same as with human development teams."
  6. Opus 4.6 was the trust threshold. "Very confident" it won't do anything stupid for problems he's seen it tackle.
  7. The exhaustion is real and may save us. After 2 hours of managing 3 projects, he's done. The biological limit prevents "1000x engineer."
  8. Open source demand is collapsing for component-level libraries. But agents love and depend on open source more than ever.
  9. Sandboxing is the only real security answer. The "lethal trifecta": private data + malicious instructions + exfiltration. Cut off one leg.

Notable Quotes

"Right now, I write more code on my phone than I do on my laptop."

— Simon Willison

"Tests are no longer even remotely optional."

— Simon Willison

"Nobody writes any code, nobody reads any code — which is clear insanity. That is wildly irresponsible. [But] it turns out you can do this if you think really hard about how agents prove to you that the stuff they've written works."

— Simon Willison

"I end up with code that is way better than the code I would have written by hand because I'm a little bit lazy."

— Simon Willison

"After two hours of that, I'm done for the day. Mentally exhausted. I think that might be what saves us."

— Simon Willison

Data Points

45-49%Speedup on Fibonacci benchmark (backstage optimization)
5Tokens: "use red green TDD"
~2 hrsBefore mental exhaustion
3Go projects in 2 weeks (non-fluent)

Connections to Our Work

  • Conformance-driven development for migrations. Take existing migration implementations → extract a conformance suite → validate new migration types. Try this week.
  • TDD-first agent workflows. Every migration agent should start with use red green TDD. Highest-ROI instruction.
  • Template/exemplar strategy. The first migration of each type must be excellent because every subsequent one follows its patterns.
  • Design for 2-4 hour deep work windows. Async-first, notification-batched, "check when ready" patterns.
Talk 10

Building When It Feels Like There's Nothing Left to Build

Chip Huyen — Author of AI Engineering & Designing Machine Learning Systems

TL;DR

The most philosophical talk. Huyen grapples with the existential crisis: anything you create can be replicated by AI within a day. Her answer: build because it brings joy, because problems follow a long-tail distribution AI can't cover, and because human preference is deeply personal. She also delivers sharp observations about AI's inefficient web search and irreversible actions in the physical world.

Key Insights

  1. "The Ghibli moment of software." Just as AI made any art style reproducible, AI code generation makes any describable software reproducible.
  2. Long-tail problems are the moat. AI excels at common problems. Edge cases, cultural nuances form a long tail AI can't fully cover.
  3. Cultural nuances are vastly underestimated. Vietnamese voice bots vs. American text chatbots — response timing differs by 120-220ms between cultures.
  4. Irreversible actions are the real danger. Form submissions, financial transactions — these can't be undone.
  5. The world isn't agent-ready. Rate limits, websites, books — all built for humans, need rebuilding for agents.
  6. AI web search is embarrassingly inefficient. Agents visit 900-1,000 URLs per query but only ~20 are unique.
  7. "Claude just wiped out my Postgres locally." Found the port taken, removed the existing instance.
  8. Code review as education is broken. Senior reviews junior's AI code; junior doesn't read feedback: "I'm not the one writing the code."
  9. Building as gift-giving. Custom apps as birthday presents. The purest relationship with AI-era development.

Notable Quotes

"I fluctuate between excitement and despair. On one hand, I can build anything I want. On the other hand, anyone can build anything I want."

— Chip Huyen

"Claude just wiped out my Postgres locally… it was trying to create a new app and was like, 'Wait, this port is taken, let me just remove it.'"

— Chip Huyen

"I hope we can normalize building things for fun."

— Chip Huyen

Data Points

300KViews in one week on her project
< 1 daySomeone cloned her project with Claude
900-1KURLs visited per AI search query

Connections to Our Work

  • Long-tail migration problems — design the system to gracefully hand off edge cases where human expertise remains essential.
  • Irreversible migration actions — build explicit reversibility checks. If not rollback-able, require human approval.
  • Code review reinvention — what does migration review look like when neither author nor reviewer wrote the code? Intent review? Conformance checking?

Talk 12

Entire.io and Closing of The Pragmatic Summit

Thomas Dohmke (Co-founder, Entire.io / ex-CEO of GitHub) with Gergely Orosz closing

TL;DR

Dohmke launches "Checkpoints" — an open-source CLI capturing developer intent (prompts, reasoning, corrections) alongside code changes. The thesis: in an agentic world, prompt history is more important than code history. GitHub's file-browser paradigm is obsolete for agentic development, and code review of AI-generated code is fundamentally broken.

Key Insights

  1. Prompt history > code history. When nobody writes or reads code, the history of intents matters more than file diffs.
  2. GitHub's file-browser paradigm is obsolete. "A glorified file browser." If you never look at code, why are repos organized as folders and files?
  3. Institutional knowledge is the real loss. WHY decisions were made is never codified. With massive AI code churn, this gets exponentially worse.
  4. Merge conflicts could be resolved by replaying intent. Replay the original prompt on the merged codebase instead of resolving at the code level.
  5. No technology ever truly goes away. Cobol still exists. GitHub won't disappear — Entire sits alongside it "like Figma to Adobe."

Notable Quotes

"We are no longer thinking in code. We are thinking in human language."

— Thomas Dohmke

"When you go to a GitHub repository today, what you're looking at is a glorified file browser."

— Thomas Dohmke

"Raise your hand if you are happy about reviewing your co-worker's 10,000 lines of AI slop. The worst dream of every developer."

— Thomas Dohmke

Connections to Our Work

Cross-Talk Themes

Theme 01

The Bottleneck Keeps Moving

Every single speaker identified that code generation is solved or nearly solved. The constraints have shifted downstream.

  • OpenAI: Code gen → code review → CI/CD → understanding users
  • Cursor: Authoring → testing → verification
  • Uber: Authoring → review → measurement → cost
  • Forsgren: Inner loop → review, deployment, release, security (the entire "outer loop")
Implication: Build the downstream infrastructure: automated review, testing, validation, and campaign management.
Theme 02

Simplicity Wins (Again and Again)

  • Vercel deleted their complex agent → 50 lines + bash + SQL
  • Ramp started with 5 eval data points and iterated
  • Willison: use red green TDD — 5 tokens
  • Beck: "What's the smallest experiment I can run?"
Implication: Start with the simplest possible agent. Add complexity only when real failures demand it.
Theme 03

Context > Model Quality

  • Atlassian: RoboDev beats Claude Code with Claude's own model (teamwork graph)
  • Uber: MCP + docs + Jira = better performance
  • Ramp: Employee role/title > model upgrades
  • Fowler: DDD language makes agents more efficient
  • Willison: Agents follow existing patterns perfectly
Implication: Context engineering is the highest-leverage investment. The model is a commodity; the context is the moat.
Theme 04

Toil is the Killer App

  • Uber: 70% of agent workloads are toil
  • Vercel: Software maintenance is the exciting frontier
  • Huyen: Common problems (top of distribution) are AI territory
  • Willison: 3 Go projects in 2 weeks by a non-fluent programmer
Implication: Migration automation is perfectly positioned. Toil has the highest accuracy and builds the most trust.
Theme 05

Adoption is a People Problem

  • Uber: 24-minute magic demo → slow adoption; peer-to-peer wins
  • Ramp: Cultural alignment is prerequisite
  • Forsgren: Explicit exec sponsorship makes a "huge difference"
  • Beck: Organizational incentives actively resist improvement
Implication: Invest in internal champions, shared wins, and progressive trust-building. Even if AI is better, incentives may resist it.
Theme 06

Cost is the Elephant in the Room

  • Uber: 6x cost increase since 2024
  • Dohmke: Token costs "through the roof"
  • Vercel: One engineer was 10x cost due to cache misses
  • Huyen: AI search visits 900-1000 URLs (~20 unique) — massive waste
Implication: Build cost observability from day one. Own the narrative before finance forces it.
Theme 07

Role Collapse and the Manager Instinct

  • OpenAI: Designers ship more code than engineers
  • Cursor: Engineers becoming "managers" of agent fleets
  • Linear/Flint: Non-engineer designers shipping 5-6 PRs/week
  • Beck: "6 tools ≠ 6 teammates" — don't let this become re-soloing
Implication: The Staff+ role evolves toward orchestrator of automated systems. Maintain human collaboration alongside agent orchestration.
Theme 08

Verification > Generation

  • Willison: TDD is mandatory — agents make it free
  • Beck: "When you've got a big powerful genie, you really have to learn how to verify"
  • Forsgren: Some companies REMOVED automated review when AI entered
  • Dohmke: Review AI slop is "the worst dream of every developer"
Implication: Build verification infrastructure. Conformance suites, automated quality gates, intent-based review.
Theme 09

The Human Limit is Real

  • Forsgren: 3-4 hours of deep work per day, max
  • Willison: "After 2 hours, I'm done. Mentally exhausted."
  • Beck: Agent slowness is a feature — gives time to talk
  • Hashimoto: Turns off all agent notifications
Implication: Design for 2-4 hour deep work windows. Async-first, notification-batched. The 1000x engineer is biologically impossible.
Theme 10

Nobody Reads the Code (And That Might Be OK)

  • Willison: "Nobody writes code, nobody reads code" — works with verification
  • Huyen: Juniors don't read senior review feedback on AI code
  • Dohmke: Prompt history > code history — review intent, not implementation
  • Fowler: "What do you mean by code? We're at least doing prompting"
Implication: Evolve from code review to intent review + conformance verification. "Did the agent fulfill the intent and pass all checks?"

The Meta-Narrative

The Pragmatic Summit 2026 tells a single coherent story: The era of code generation is ending. The era of code orchestration is beginning. The headliner talks (Forsgren, Fowler, Beck, Willison, Huyen) deepen this into something more profound: we are mourning the old craft while inventing the new one, and nobody knows what the new one looks like yet.

Every speaker has accepted that AI writes code at least as well as most humans. That's no longer controversial — it's boring. What's not boring is everything that follows:

  1. Phase 1 (2022-2024): Augmentation. Copilot, tab completion, 10-15% productivity gains. Pair programming.
  2. Phase 2 (2025): Delegation. Background agents, Cursor/Claude Code, async task execution. Peer programming. Coding "got solved."
  3. Phase 3 (2026+): Orchestration. Self-driving codebases, campaign management, multi-agent fleets, engineers as tech leads of agent teams.
  4. Phase 4 (emerging): Intent-Driven Development. The code becomes ephemeral; the intent is permanent. Documented reasoning, conformance specs, and domain models that agents translate into implementations.

The deeper story is about where value concentrates in this new world:

  1. Context is more valuable than compute. Every winning company wins because of proprietary context, not better models.
  2. Taste is more valuable than speed. Homer's car is the cautionary tale. The ability to say "no, not that" is the scarce resource.
  3. Verification is more valuable than generation. Anyone can generate code. Building the infrastructure to trust it is the hard problem.
  4. Adoption is harder than building. Organizational incentives actively resist improvement. Change management is now the dominant engineering challenge.
  5. Craft satisfaction is shifting, not dying. Beck mourns perfecting one function. But new satisfactions emerge: managing 3 projects simultaneously, building gifts for friends, achieving 10x quality.
  6. The human limit bounds everything. 3-4 hours of deep work. 2 hours of agent management. "1000x engineers" are fantasy. "10x leverage within human bandwidth" is realistic.

The summit's implicit message to platform engineers: You are building the infrastructure for the most important transition in software engineering since the internet — and possibly since the microprocessor. Kent Beck and Martin Fowler, with 50 years of perspective, confirm: they've never seen change this fast.

Action Items

1

Frame migration automation as "campaign management." Uber's Shephard concept (YAML-defined migrations → auto-generated PRs → tracking → notification) is the mature version. Use this as the architecture reference.

2

Build model-facing DevX. Audit whether repos, services, and docs are navigable by agents. A new dimension of platform engineering.

3

Invest in a prompt quality layer. Uber's pattern — analyzing prompts before execution — directly reduces failed tasks and builds trust.

4

Start measuring business outcomes now. Before the CFO asks. Instrument from design → experiment in production. Show time compression, not just more PRs.

5

Build cost observability from day one. Trace token costs per team, per project, per migration type. Own this narrative before finance forces it.

6

Drive adoption through champions, not mandates. Find 3-5 power users, document wins, share widely. "Engineers trust other engineers."

7

Start evals with 5 golden examples. Build a simple eval harness, start with 5 correct cases, grow incrementally. Run in CI.

8

Consider "one agent with a thousand skills." Shared framework with pluggable migration skills and a common tool catalog.

9

Implement the autonomy slider. Let teams control trust in AI-generated migrations. Start with suggestions, let them pull toward auto-merge.

10

Read the Ramp Inspect open source blueprint at builders.ramp.com — reference implementation for internal AI developer tools.
